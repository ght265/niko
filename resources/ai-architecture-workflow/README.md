# AI 建筑设计与 SketchUp 参数化建模工作流

用于把经核实的资料、人工设计决策和可重跑的脚本串起来。首个案例为[广州美术馆](../../projects/guangzhou-art-museum/README.md)。

| 阶段 | 工作 | 交付与确认门槛 |
| --- | --- | --- |
| G0 资料接收 | 建资料台账、声明范围与公开权限 | 负责人确认任务书、资料来源和缺项 |
| G1 场地基线 | [提取 CAD 并核对坐标](site-and-cad.md) | 原图索引、图层映射、基准、控制点和复测结果获确认 |
| G2 概念与约束 | 按同一基线比较策略，记录功能邻接、平剖关系、流线与取舍 | 方案卡、功能面积表、约束与参数表、决策记录获确认 |
| G3 建模 | [分阶段生成并校核](modeling.md) | 参数快照、脚本提交、SKP 副本、复跑及几何证据获确认 |
| G4 可视化与发布 | [D5 同步和版本交付](d5-and-release.md) | 可重新打开的发布包及[签核清单](checklists.md) |

[提示词](prompts.md)随各阶段使用。复用时复制案例的入口、任务书、参数表和日志到新的 `projects/<slug>/`，清空项目专属资料和状态，继续链接本通用目录。阶段可循环。变更单位、坐标、红线、关键参数或已批准方案时，追加决策记录并重开受影响的后续校核。

## 数据状态

- **已确认**：有可定位来源及人工审核。记录版本、单位、审阅者和适用阶段。允许进入对应几何基线。
- **待补充**：缺资料、精度、口径或审核，或来源存在冲突。数值留空，并记录影响阶段。
- **假设**：用于方案对比，记录理由、验证条件和影响范围。留在单独试验版本，经审阅后才可升格。

参数表应区分硬约束、设计变量和派生指标，可在实例中加列记录类别、公式及依赖 ID。面积与高度同时注明计算边界和标高基准。缺项保留为空，零值只有在资料明确支持时才填写。
