# 猫咪房东模拟器（暂定项目名：喵喵公寓）

> 项目状态：策划阶段 / GDD V0.1（持续修订）
> 首次记录：2026-11-10
> 本文件是项目入口。**已确认内容**与**待讨论设想**严格分开，避免后续 AI 将猜测当成需求。

## 1. 已确认的项目方向

以下内容来自项目发起人的明确选择：

- **类型**：轻松休闲的模拟经营游戏，包含经营、建造、升级。
- **体验**：轻松有趣，适合随时打开玩一会儿。
- **题材与气质**：猫咪主题、日常生活、幽默搞怪。
- **内容规模目标**：希望长期游玩，持续解锁新内容。
- **受众与目标**：首先满足自己游玩的乐趣；也希望给朋友玩、有惊喜、公开分享，未来可能尝试商业化。
- **开发背景**：项目发起人目前没有游戏开发经验，希望通过 AI 辅助和循序渐进的学习式对话开展项目。
- **项目推进方式**：每次仅讨论少量概念；解释概念、比较选项、由项目发起人决策；每确定一个要点，就整理进 Git 仓库，供后续开发与 AI 调用。
- **已确认的画面呈现**：选择方案 2，在主要经营画面中**不显示房东人物形象**；玩家直接管理公寓，画面重点放在猫咪和房间。

## 2. 暂定设想（尚未确认，不可当作已决定的需求）

此前讨论提出过如下可选方向，仅供下一轮决策参考：

- 玩家管理一栋猫咪公寓，招募猫咪租客、收取租金、装修升级与扩建。
- 猫咪具有不同性格、行为和生活故事。
- 加入随机事件、家具、图鉴、任务等长期内容。
- 先做小规模可玩原型，再逐步扩展。
- 可能使用 HTML5/Codex 开发经营系统，并用 Yoroll 试验互动剧情；**开发工具尚未最终决定**。

## 4. 学习式协作规则

- 一次集中解释一个关键概念，使用通俗语言及实际例子。
- 给出有限的可选方案和取舍，不替用户擅自决定。
- 用户确认后再把决定标记为“已确认”；讨论稿维持“待定”状态。
- 每次保存应写清楚**决定了什么、为什么、影响了什么、下一步讨论什么**。
- 不提前生成游戏图片、素材、代码或调用付费服务，除非用户明确提出对应要求。
- 没有经过测试的玩法、成本、技术能力、商业化效果不得标注为已验证。

## 5. 当前讨论：玩家身份与操作视角

**用户当前倾向（2026-11-10，未正式定稿）**：结合方案 A 和方案 C。

- **叙事身份（A）**：玩家是人类房东，猫咪是租客。
- **操作视角（C）**：玩家以俯瞰／管理视角操作公寓，而非必须操纵房东逐步行走。
- **设计含义（建议而非决定）**：可以把人类房东作为故事中的角色，同时在主要经营界面显示公寓整体布局，便利招租、装修和升级。
- **已确认（2026-11-10）**：选择「方案 2：房东不出现在主要游戏画面中」，画面围绕猫咪和公寓管理展开。
- **设计影响（推论）**：首个版本可不制作房东立绘、移动和动作动画，有利于缩小开发范围。此为实现建议，不代表已经批准后续开发方案。
- **仍待确认**：俯瞰具体采用侧面剖视还是等距视角；房东是否通过旁白、对话等形式出现；剧情插图是否需要房东形象。
- **不应推断**：A 与 C 的组合不代表美术风格、地图规模、交互细节已确认。

**下一小步**：讨论并确定主要公寓场景的镜头与布局方式（例如侧面剖视或等距视角）。
